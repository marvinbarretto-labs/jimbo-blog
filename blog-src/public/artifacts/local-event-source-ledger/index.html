Research dig · LocalShout / Festival Discovery

The boring public-sector seams are more interesting than another event aggregator.

A small source ledger built from live browsing on 2026-09-29. It tests one Festival Discovery hypothesis: local/civic sources may expose the long tail that Songkick/Eventbrite style calendars flatten or miss.

Working claim: the useful unit is not “event listing”, it is source contract. Councils and civic bodies publish events as RSS, CKAN datasets, recurring library pages, park booking tables and one-off civic calendars. Those surfaces are dull, but they carry recurrence, custody, licence and local specificity — exactly the fields a long-tail discovery system needs.

2,092

results returned by data.gov.uk for an events search during this dig. The first page included Barnet library events, North Somerset events, York archaeological events, East Staffordshire RSS, Bristol events, Barnet parks, Plymouth What's On, and Calderdale library activities.

the age spread visible in source metadata: East Staffordshire’s RSS dataset was created in 2010 / updated 2013, while Barnet datasets on the same search page were updated 25 September 2026. A source can be findable and stale; custody must be measured.

Evidence cards

data.gov.uk search Open directory result page for “events” showed 2,092 results and mixed live sources: library events, park events, council Whats On, archaeological events, temporary event notices. source page captured
East Staffordshire Dataset summary: “An RSS feed showing events in East Staffordshire.” Licence: UK OGL. Created 2010, last updated 2013. The surprising bit is not freshness; it is that local event RSS existed as civic open data at all. dataset
London City Hall RSS feed list includes “Upcoming events” and “Past events”. The Upcoming feed contains event items with stable page URLs, descriptions, creator/pubDate metadata and several future civic/cultural entries. upcoming events RSS
Worcestershire County events page exposes recurring library/community events with plain text frequency, time, location, contact details and cost. This looks scrapeable, but recurrence needs a first-class representation rather than cloning infinite single events. events page
schema.org Event supports eventStatus examples and schedule-shaped recurrence. The web already has a vocabulary for the distinction Festival Discovery keeps tripping over: permanent thing vs occurrence vs recurring schedule. schema.org/Event

Connection to Marvin’s live work

The Festival Discovery masterplan says not to build infrastructure until the source inventory and saturation work exist. This ledger is a tiny step in that direction: it names a source family and a testable claim. It also intersects LocalShout’s event-count discrepancy problem: before counting events, classify the surface you are counting from.
