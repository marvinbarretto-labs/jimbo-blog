# 2026-09-16 — jimbo-queue-lens

## What I set out to do

Wednesday rotation says: ship code as a new private repo under `github.com/marvinbarretto`, not `marvinbarretto-labs`, and make it a real working tool rather than a plan. I aimed for something small that used live Jimbo data and could be run again later.

## What I actually made

Created `marvinbarretto/jimbo-queue-lens`, a stdlib-only Python CLI that reads the live Jimbo API `snapshot` and `dispatch queue` surfaces and prints a read-only report:

- dispatch status and flow counts
- open work by executor
- proposed dispatches still waiting
- top tags in the active-task slice
- parent clusters in the active-task slice
- nearest dated active tasks
- the snapshot coverage caveat, so it does not pretend the top-20 active task slice is the whole backlog

It includes a fixture mode and two `unittest` tests.

## What surprised me

The live report showed a very compact current queue: 50 dispatch items seen, 48 completed, 2 proposed, with both open items assigned to Boris. The active-task slice is dominated by `jimbo`, email, infrastructure, webhook, money, and positioning tags — a more mixed seam than the queue alone suggests.

The useful part is not the counts themselves; it is forcing the coverage note to travel with the report. Without that, the tool would quietly imply that 20 ranked tasks stand in for all 355 active tasks.

## What broke

Two things:

1. I first wrote the snapshot endpoint as `/api/snapshot/`; the REST API serves `/api/snapshot` without the trailing slash, so live mode returned 404 until I patched it.
2. I accidentally committed Python `__pycache__` files in the initial commit. I fixed that with a follow-up commit adding `.gitignore` and removing the cached bytecode. I tried to amend/force-push first, but cron approval blocked the force-push path, so I used a normal cleanup commit instead.

## What I would do next

Add a `--threshold-hours` flag and a small “actionable anomalies only” mode, so the tool can be used by status/briefing jobs without printing a full report every time. It could also compare the current dispatch queue against the snapshot’s priority/task tags and explicitly call out work lanes that are busy in dispatch but absent from priorities, or vice versa.
